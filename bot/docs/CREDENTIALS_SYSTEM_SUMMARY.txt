DATABASE MODELS
================================================================================

DydxCredential:
  - id (PK)
  - user_id (FK)
  - network_type (enum: testnet, mainnet)
  - address (encrypted)
  - mnemonic (encrypted)
  - is_active (bool)
  - is_test_valid (bool)
  - last_tested (datetime)
  - created_at, updated_at (timestamps)
  - created_by, updated_by (user IDs)
  - name, description (metadata)
  - error_message (last error)

Indexes:
  - (user_id, network_type)
  - (network_type, is_active)
  - (user_id, is_active)

DydxCredentialAudit:
  - Tracks all CRUD operations
  - Stores operation type, success status
  - Records address_preview (first 20 chars)
  - Complete user and timestamp tracking

DydxTestResult:
  - Records each credential test
  - Stores response time and results
  - Tracks connectivity and balance info
  - Useful for debugging and monitoring

================================================================================
API ENDPOINTS
================================================================================

All endpoints require: Authorization: Bearer <JWT_TOKEN>

1. CREATE CREDENTIAL
   POST /api/v1/dydx/credentials
   Request: network_type, address, mnemonic, name, description, test_before_save
   Response: credential ID, address_preview, test results
   Status: 201 Created / 400 Bad Request / 503 Service Unavailable

2. LIST CREDENTIALS
   GET /api/v1/dydx/credentials?network_type=testnet&active_only=true
   Response: Array of credential summaries
   Status: 200 OK

3. GET CREDENTIAL
   GET /api/v1/dydx/credentials/{id}?decrypt=false
   Response: Full credential details (encrypted by default)
   Status: 200 OK / 404 Not Found / 403 Forbidden

4. UPDATE CREDENTIAL
   PUT /api/v1/dydx/credentials/{id}
   Request: Any subset of (address, mnemonic, name, description, is_active)
   Response: Update confirmation
   Status: 200 OK / 400 Bad Request / 403 Forbidden

5. DELETE CREDENTIAL
   DELETE /api/v1/dydx/credentials/{id}
   Response: Empty (soft delete)
   Status: 204 No Content / 403 Forbidden

6. TEST CREDENTIAL
   POST /api/v1/dydx/credentials/{id}/test
   Response: Test results (success, response time, balance, error message)
   Status: 200 OK / 503 Service Unavailable

7. GET CREDENTIAL STATUS
   GET /api/v1/dydx/credentials/{id}/status
   Response: Status info (active, test_valid, can_be_used)
   Status: 200 OK / 404 Not Found / 403 Forbidden

================================================================================
ENCRYPTION DETAILS
================================================================================

Algorithm: Fernet (symmetric)
  - AES-128 in CBC mode
  - HMAC authentication
  - Timestamp validation
  
Key Management:
  - Generate: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  - Store in CREDENTIALS_ENCRYPTION_KEY env var
  - Never commit to version control
  - Rotate periodically

Data Flow:
  Plain text → Fernet encryption → Base64 encoding → Database storage

Security:
  ✓ Tamper detection via HMAC
  ✓ Time-based expiration possible
  ✓ Industry standard encryption
  ✓ No master key in code
